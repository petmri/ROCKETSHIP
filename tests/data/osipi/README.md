## Ground-truth data provenance

The DCE model datasets are **byte-identical (MD5) to the OSIPI source** at commit
`23d3714` (`test/DCEmodels/data/`). Per the OSIPI source docstrings the concentration
curves were generated by M. Thrippleton with
[mjt320/DCE-functions](https://github.com/mjt320/DCE-functions), and each row's
`vp/ve/fp/ps` (or `Ktrans/ve/vp`) columns are the **true parameters used to generate
the data**. Published in Manning et al., *Magnetic Resonance in Medicine*, 2021
([doi:10.1002/mrm.28833](https://doi.org/10.1002/mrm.28833)).

## Tolerances: two distinct files (do not confuse them)

**1. OSIPI official acceptance tolerances — the hard gate.**
`reference/osipi_official_tolerances.json` is transcribed **verbatim** from the OSIPI
test suite (`test/DCEmodels/DCEmodels_data.py` @ `23d3714`), where every contributor
implementation is asserted with
`np.testing.assert_allclose(measured, reference, atol=a_tol, rtol=r_tol)`. These are
round, method-agnostic, fully reproducible pass/fail bars. **The DCE reliability and
fast-backend tests gate on these** (via `tests/python/osipi_official_tolerances.py`).

**2. Peer-implementation error spread — reproducible, informational only.**
`reference/osipi_peer_error_summary.json` (and its human summary
`reference/peer_accuracy_summary.md`) hold the pooled error spread (mae / p90 / p95 /
max of |measured − reference|) of every published contributor implementation in the
OSIPI DCE-DSC-MRI testing framework — the multi-software comparison published in
**van Houdt et al., *Magnetic Resonance in Medicine*, 2023**
([doi:10.1002/mrm.29826](https://doi.org/10.1002/mrm.29826)).

- **Fully reproducible.** Every per-contributor result CSV (`*_ref` vs `*_meas`) is
  committed under `reference/{dce_models_results,t1_mapping_results,si_to_conc_results,
  dsc_models_results}/`, mirrored from `test/results/` in the upstream repo.
  `reference/generate_peer_error_summary.py` recomputes the JSON from them exactly
  (verified to machine precision, `--check`).
- **Not a gate — near-circular for LEK-ported models.** The pool *includes* the
  LEK/Edinburgh implementation that ROCKETSHIP ports (`2cxm`, `tissue_uptake`); our fit
  reproduces LEK, so `peer max` tracks our own error to ~4 significant figures. Reported
  for context by the summary generator and `run_osipi_reliability.py`, never gated.
- **The OSIPI tolerances are validity checks, not accuracy bars.** The paper states they
  were set "wide... not intended to indicate an acceptable level of accuracy" (to catch
  gross/unit errors). Our official-tolerance gate is therefore a validity gate; the peer
  spread is the finer accuracy context.

## Regenerating the artifacts

**Peer error summary** — `reference/generate_peer_error_summary.py` pools every committed
per-contributor result CSV and recomputes `osipi_peer_error_summary.json` (mae / p90 / p95
/ max per category·method·parameter). This is *how that JSON was generated*; it reproduces
the committed file to machine precision.

```bash
.venv/bin/python tests/data/osipi/reference/generate_peer_error_summary.py --check  # verify
.venv/bin/python tests/data/osipi/reference/generate_peer_error_summary.py          # rewrite
```

**Accuracy summary + figures** — `reference/generate_osipi_summary.py` fits every DCE/T1
dataset with the same reference functions the tests gate on, then writes a plain-markdown
report (provenance, dual-gate accuracy table, per-case ground-truth-vs-fit tables) plus
figures:

```bash
.venv/bin/python tests/data/osipi/reference/generate_osipi_summary.py
# -> docs/project-management/projects/osipi-verification/osipi_summary.md
# -> tests/data/osipi/reference/figures/*.png
```
