# BIDS_test — DCE/T1 parity & phantom-qualification fixtures

Small BIDS-style dataset used by the ROCKETSHIP test suite for two purposes:

1. **MATLAB ↔ Python parity** on real-style data (`sub-01original` and its variants).
2. **Synthetic-phantom ground-truth qualification** — fitting known parameter maps and
   scoring recovery (`sub-05phantom` … `sub-09phantom`).

The canonical BIDS metadata lives in [`rawdata/`](rawdata/):
[`participants.tsv`](rawdata/participants.tsv) (one row per subject),
[`participants.json`](rawdata/participants.json) (column dictionary), and
[`dataset_description.json`](rawdata/dataset_description.json).

## Layout

```
BIDS_test/
├── rawdata/            # BIDS raw dataset root (participants.tsv lives here)
│   └── sub-XX*/ses-01/{anat,dce,gt}
└── derivatives/        # preprocessed inputs the pipeline actually consumes
    └── sub-XX*/ses-01/{anat,dce}
```

- **anat** — variable-flip-angle (VFA) images for T1 mapping, plus a `T1w` on the reference.
- **dce** — the dynamic series. For `sub-01…04` the usable 4-D DCE image is the preprocessed
  derivative `derivatives/.../dce/*desc-bfcz_DCE.nii.gz` (rawdata holds only the JSON sidecar);
  for the phantoms the 4-D DCE image is present directly in `rawdata/.../dce/`.
- **gt** — ground-truth assets, phantoms only (see below).

> **Filename quirk:** every subject's files are named `sub-01_ses-01_*` regardless of the
> containing subject folder (e.g. `sub-07phantom/ses-01/dce/sub-01_ses-01_DCE.nii.gz`). The
> **folder name** is the authoritative subject label; the in-file `sub-01` prefix is an
> artifact of how the fixtures were copied and does not indicate subject identity.

Full per-column definitions are in [`rawdata/participants.json`](rawdata/participants.json).

### Real-derived subjects (`sub-01…04`)

Produced by [`tests/matlab/generate_synthetic_datasets.m`](../../matlab/generate_synthetic_datasets.m)
from `tests/data/BIDS_example` sub-01 (`noisy_low`, `noisy_high`, `downsample_x2` variants). They
share the reference acquisition metadata (TR 8.012 ms, Δt 15.36 s, DCE flip 15°, VFA 2/5/10°) and
carry **no** ground truth — they exist to exercise the pipeline and MATLAB↔Python parity under
controlled perturbations.

### Synthetic phantoms (`sub-05…09`)

Generated by `synthetic_dce.generate_synthetic_data_gpu` (recorded in each DCE sidecar under
`GeneratedBy` / `SyntheticPhantom`). Common properties: 64×64×6 grid, **Parker** AIF, hematocrit 0
with a plasma-kind AIF (`PlasmaCorrectionApplied=false`), relaxivity ≈5.2 mM⁻¹s⁻¹. Each phantom's
`SyntheticPhantom` sidecar block records its per-subject relaxivity, AIF pre-contrast T1, AIF ρ,
baseline-frame count, and (for the low-noise pair) SNR range, seed, and VFA flip angles.

Ground truth in `ses-01/gt/` (BIDS `desc-gt*` naming):

- **Maps:** `desc-gtT1_T1map`, `desc-gtKtrans_map`, `desc-gtVe_map`, `desc-gtVp_map`, `desc-gtFp_map`.
- **Masks:** `desc-gtTissueClass_mask` (**0**=background, **1**=muscle/fat, **2**=brain, **3**=vessel),
  `desc-gtAIFMask_mask`.
- **AIF:** `desc-gtAIF_timeseries.txt` (+ `.json`) — columns `frame_idx, time_min, aif_gd_mM, aif_si_norm`.

The DCE forward model used to synthesize the phantom curves is more complex than the standard
fitted models (Tofts/ex-Tofts/Patlak), so some systematic recovery bias is expected by design;
see [`docs/project-management/projects/phantom-gt/PHANTOM_GT_QUALIFICATION_STATUS.md`](../../../docs/project-management/projects/phantom-gt/PHANTOM_GT_QUALIFICATION_STATUS.md).

## Consumers

- `tests/python/phantom_gt_helpers.py` / `run_phantom_gt_reliability.py` / `test_phantom_gt_reliability.py`
  — phantom GT recovery (MAE + ground-truth-in-CI coverage) over `sub-05…08`.
- Parity and qualification tests reference `sub-01…04` for pipeline and MATLAB↔Python checks.
